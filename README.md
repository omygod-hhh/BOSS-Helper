# BOSS 自动沟通 Helper（boss.user.js）

> 🚨 **重要：boss直聘需要关闭自动打招呼功能！！！**
> 使用本脚本前，请先在 BOSS 直聘 App / 网页的「设置 → 隐私 / 沟通设置」中，**关闭平台自带的「自动打招呼 / 自动回复」功能**。否则平台自带自动打招呼会和本脚本同时发送消息，造成重复沟通、节奏失控，更容易触发账号风控。

一个运行在 **[Tampermonkey（篡改猴）](https://www.tampermonkey.net/) / 油猴** 中的 BOSS 直聘（zhipin.com）自动打招呼用户脚本。它会在岗位列表页自动选择岗位、进入聊天页、发送常用语或自定义问候语，并把已沟通的岗位数据记录下来，支持按公司 / 活跃度 / JD 匹配度做筛选，以及断点续跑与数据导出。

> ⚠️ 免责声明：本脚本仅用于个人自动化操作研究。请遵守 BOSS 直聘的用户协议与平台规则，控制沟通频率，避免对他人造成骚扰或触发账号风控。

---

## 一、环境要求

- 浏览器：Chrome / Edge / Firefox 等支持油猴插件的桌面浏览器
- 插件：**Tampermonkey（篡改猴）** 或兼容的用户脚本管理器
- 账号：已登录的 BOSS 直聘网页账号（https://www.zhipin.com）
- 本地服务（可选）：如需使用「JD 智能匹配 - 本地 Ollama」或「接口返回问候语」，需在本机运行对应服务（Ollama 默认地址 `http://localhost:11434`）

---

## 二、安装步骤

1. 安装好 Tampermonkey 浏览器插件。
2. 打开 Tampermonkey 管理面板 → **「添加新脚本」**。
3. 清空编辑器内容，把本目录下的 `boss.user.js` 全部内容粘贴进去。
4. 按 `Ctrl/Cmd + S` 保存（或点击「文件 → 保存」）。
5. 确认脚本已**启用**（插件图标上应显示绿点 / 启用状态）。

> 脚本头部已声明匹配规则（`@match`），仅会在以下页面生效，无需手动配置域名：
> - `https://www.zhipin.com/web/geek/jobs*` （岗位搜索 / 推荐列表页及其子路由）
> - `https://www.zhipin.com/web/geek/chat*` （聊天页）

---

## 三、面板入口与基本使用

安装并打开 BOSS 直聘的岗位列表页（或聊天页）后，页面**右侧**会出现一个控制面板：

- 面板标题为「BOSS 自动沟通 / 岗位问候自动化」。
- 右上角「沟通」小按钮可随时**收起 / 展开**整个面板。
- 顶部「板块管理」按钮（齿轮/方块图标）可开关各个功能板块的显示。

### 最快上手（默认即可用）

1. 打开岗位列表页，确认右侧面板已出现。
2. 在「打招呼配置」里选择问候语来源：
   - **常用语**：点击「选择常用语」从 BOSS 账号里的常用语列表挑一条（脚本会先拉取你账号的常用语）。
   - **自定义文本**：直接在文本框里写问候语，支持占位符（见下文）。
3. 在「运行策略」里按需调整最小/最大间隔（默认 4~8 秒，避免过快）。
4. 点击面板底部的绿色 **「启动」** 按钮，脚本开始自动沟通。
5. 需要中断时点击红色 **「停止」** 按钮。

## 四、功能板块详解

面板按「板块」组织，可在板块管理里隐藏不常用的板块。核心板块如下：

| 板块 | 说明 |
| --- | --- |
| 打招呼配置（固定开启） | 配置发送什么内容：常用语 / 自定义文本 / 接口返回 |
| 运行策略（固定开启） | 自动化节奏与边界控制 |
| 公司筛选 | 只沟通名称匹配某关键词的公司（或只排除） |
| 公司黑名单 | 命中即跳过的公司名单，支持部分/全量/正则匹配 |
| Boss 活跃度筛选 | 只沟通指定活跃度（在线 / 今日活跃 / 3 日内活跃…）的 Boss |
| JD 智能匹配 | 按关键词或本地模型评估岗位匹配度，达阈值才投递 |
| 数据导出 | 把已沟通岗位记录导出为 JSON / Excel |
| 数据清理 | 按时间删除或清空已沟通记录 |
| 调试日志 | 记录运行诊断事件，便于排查（默认关闭） |
| 已沟通列表 | 以虚拟列表展示已沟通岗位，可滚动浏览 |

### 1. 打招呼配置

三种问候语来源（位于「自定义文本来源」分段选择）：

- **手动输入（自定义文本）**
  - 文本框内支持占位符，运行时会替换为当前岗位信息：
    - `{jobName}` 岗位名
    - `{company}` 公司名
    - `{salary}` 薪资
    - `{bossName}` Boss 昵称
  - 默认文本：「您好，我对这个岗位比较感兴趣，希望可以进一步沟通，谢谢。」
- **接口返回（自定义 API）**
  - 填写一个会返回问候文本的接口地址，支持 GET/POST/PUT/PATCH。
  - 支持 URL 参数、请求头、请求体（占位符同上）；「返回文本路径」可指定 JSON 路径（如 `data.text`），留空则自动识别 `message/text/content`。
  - 适合需要动态生成个性化问候语的场景。
- **常用语（BOSS 账号常用语）**
  - 点击「选择常用语」弹出对话框，可搜索并从你 BOSS 账号的常用语里挑选；点「刷新」重新拉取。

### 2. 运行策略

| 选项 | 作用 |
| --- | --- |
| 跳过已沟通 HR | 已沟通过（IndexedDB 记录）的岗位自动跳过，不重复投递 |
| 收集已打招呼岗位信息 | 把已沟通岗位写入本地数据库，供导出 / 已沟通列表使用 |
| 无视列表刷新 | 列表自动刷新时不中断自动化，从断点继续 |
| 最小/最大间隔(秒) | 每两次沟通之间的随机等待区间，建议 ≥3 秒 |
| 等待上限(秒) | 等待聊天页 / 列表就绪的最长超时 |
| 聊天重试次数 | 点开沟通失败时的最大重试次数 |
| 最大沟通数 | 0 表示不限；>0 时沟通到该数量自动停止 |

### 3. 公司筛选 / 公司黑名单

- **匹配模式**：`部分`（包含）、`全量`（完全相等）、`正则`（正则匹配）。
- 公司筛选：只沟通名称命中的公司；留空则不过滤。
- 公司黑名单：命中即跳过；可「添加」多条规则，支持「删除选中 / 全部删除」。

### 4. Boss 活跃度筛选

- 内置选项：在线、刚刚活跃、今日活跃、3 日内活跃、本周活跃、2 周内活跃、5 月内活跃、半年前活跃。
- 可勾选多个；也可「添加」自定义活跃度选项。只沟通命中选中活跃度的 Boss。

### 5. JD 智能匹配

开启后按匹配度决定是否投递，降低无效沟通：

- **手动匹配**：填写你的技能 / 关键词（每行或逗号分隔），脚本按关键词命中计算匹配度。
- **智能匹配（推荐）**：选择**厂商** + 填写 **API Key** 即可，无需关心接口地址 / 请求头 / 请求体。
  - 内置厂商预设：DeepSeek、OpenAI、通义千问（阿里云百炼）、智谱 GLM、Kimi（月之暗面）、火山方舟（豆包）、本地 Ollama。
  - 选好厂商后，**模型名称可留空**，脚本自动使用该厂商的默认模型（如 DeepSeek 用 `deepseek-chat`）；如需指定其他模型，填在「模型名称」即可。
  - **只填厂商 + API Key** 就能跑；满足「匹配阈值(%)」才会自动投递。
  - 本地 Ollama 无需 API Key，但需本机已运行 Ollama 且模型已拉取。
  - **自定义接口（高级）**：在厂商下拉选「自定义接口（高级）」，再填写匹配接口地址 / 方法 / 参数 / 请求头 / 请求体 / 分数路径（支持 `{jobName}` / `{company}` 等占位符），适合非标准后端。
- 面板内「当前岗位得分」会显示选中岗位的实时匹配度参考。

> 安全提示：API Key 保存在浏览器 `localStorage`，仅本机当前脚本可读；不要在公共/共享电脑上保存密钥。

## 五、自动化运行与断点续跑

- 点 **「启动」** 后，脚本进入状态机：`列表选岗 → 点沟通 → 进聊天页发消息 → 返回列表继续`。
- 运行状态保存在 `localStorage`，已沟通记录保存在浏览器 **IndexedDB**（库名 `ZhipinAutoGreetingDB`）。
- **断点续跑**：若页面刷新、路由切换或被 BOSS 跳转到聊天页，重新回到列表页时脚本会自动从断点恢复（前提是未点「停止」）。
- 点 **「停止」** 会清除续跑状态，刷新后不再自动恢复。
- 部分异常（如需人工处理）会触发**暂停**，保留现场供你判断。

## 六、数据导出与清理

- **数据导出**：选择导出格式（JSON，需时自动加载 SheetJS 库导出 Excel），点击「导出岗位记录」下载已沟通岗位数据。
- **按时间删除**：填写时间后「按时间删除」清理该时间之前的记录。
- **删除所有记录**：清空全部已沟通记录（谨慎操作，软删除样式按钮）。
- **调试日志**：可「导出日志 / 清除日志」，用于问题排查（默认关闭，先在板块管理开启）。

---

## 七、配置存储说明

- 面板所有配置保存在浏览器 `localStorage`（key：`__zhipin_auto_greeting_config__`），下次打开页面自动恢复。
- 已沟通岗位数据保存在 **IndexedDB**，跨会话保留，用于「跳过已沟通」和导出。
- 调试开关与日志也有独立 key，旧版本遗留的 debug key 会在启动时自动清理。

## 八、常见问题（FAQ）

**Q：面板没出现？**
A：确认脚本已启用、且当前在 `jobs` 或 `chat` 页面；刷新页面或重新进入列表页试试。检查 Tampermonkey 是否允许该脚本在 zhipin.com 运行。

**Q：常用语列表为空？**
A：先点「刷新」重新拉取；若仍为空，可能账号没有设置常用语，改用「自定义文本」即可。

**Q：启动后很快被停止 / 风控？**
A：调大「最小/最大间隔」、关闭「无视列表刷新」、降低「最大沟通数」，控制节奏。请遵守平台规则。

**Q：Ollama 智能匹配不工作？**
A：确认本机已安装并运行 Ollama（`ollama list` 能看到模型），且模型名填写正确；默认接口 `http://localhost:11434/api/generate` 可达。

**Q：JD 智能匹配接口报错（如 HTTP 401 / 402 / 429）？**
A：这些是云厂商返回的，按状态码排查：
- **401**：API Key 无效或已过期，重新核对并粘贴密钥。
- **402**：账户余额不足 / 未开通付费，请到对应厂商控制台（如 platform.deepseek.com）充值后再试。
- **403**：密钥无权限访问该模型 / 接口，检查账号与模型权限。
- **404**：接口地址或模型名不存在，检查所选厂商与「模型名称」。
- **429**：请求过于频繁已被限流，调大「最小/最大间隔」或稍后重试。
脚本报错会附带厂商返回的原因原文，可直接对照。

**Q：数据存在哪，怎么备份？**
A：配置在 `localStorage`、记录在 IndexedDB（均按浏览器 + 域名隔离）。换设备或清缓存会丢失，重要数据请提前用「数据导出」备份。
