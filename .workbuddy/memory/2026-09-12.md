## BUG 修复：选「智能匹配」不显示接口配置块
- 根因：`saveFormToConfig` 的提前返回守卫依赖 `isModeInput`，而该方法只识别 `za-greeting-mode`/`za-text-source`，不含 `za-jd-match-mode`。单选「智能匹配」时 `eventField` 为 null、`isModeInput` 返回 false → 守卫成立 → 提前 return，`config.smartMatchMode` 从未更新（恒为 manual），随后 `applyJdMatchModeVisibility` 读旧值把接口块保持 hidden。
- 修复：把 `input[name="za-jd-match-mode"]` 加入 `isModeInput` 的匹配选择器，使 JD 匹配方式切换能正常保存并刷新可见性。

## 智能匹配改为本地 Ollama 预设（参数写死）
- 用户诉求：本地 Ollama，不想手动填任何接口参数。
- 新增常量 `OLLAMA_GENERATE_URL`(http://localhost:11434/api/generate)、`OLLAMA_DEFAULT_MODEL`(llama3)、`OLLAMA_MATCH_PROMPT`（要求模型只输出 0-100 整数）。
- `evaluateSmart` 重构：`useCustomApi=false` 时用写死的 Ollama 预设（model 来自 config.smartMatchModel，body 自动生成 `{model,stream:false,prompt}`），`responsePath` 固定 `response`；`useCustomApi=true` 才走原自定义接口逻辑。
- 配置新增 `smartMatchUseCustomApi`(默认 false)、`smartMatchModel`(默认 llama3)；`smartMatchApi*` 默认值改为 Ollama 地址/response 路径。
- UI：智能匹配模式只显示「模型名称」输入 + 「改用自定义接口」勾选；勾选后才展开原始 API 字段块（`data-jd-custom-api-block`，由 `applyJdMatchCustomApiVisibility` 控制）。
- `validateConfig`：Ollama 预设模式只要求填模型名，不再强求接口地址；手动模式才要求填关键词。
- 删除无调用的 `buildApiPayload` 死代码。

## 重构：JD 智能匹配拆分为「手动 / 智能(API)」两种模式
- 用户要求智能匹配需可接入 API；两种选择：手动匹配（关键词命中率）、智能匹配（调用外部接口返回分数）。
- 配置新增：`smartMatchMode`('manual'|'smart')，及智能模式接口字段 `smartMatchApiUrl/Method/Params/Headers/Body/ResponsePath`；`smartMatchApiParams/Headers` 加入 STRUCTURED_CONFIG_FIELD_KEYS。
- `JdMatchService` 重构：`evaluateManual`（关键词命中率）、`evaluateSmart`（GM_xmlhttpRequest 调接口，`extractScore` 用响应路径或自动识别 score/匹配度/相似度 等字段）、统一 `evaluate`(async)。
- 面板新增匹配方式单选（manual/smart），智能模式才显示接口配置块（`data-jd-match-block` + `applyJdMatchModeVisibility` 切换）。
- 智能接口异常时按「无法确认匹配」保守跳过，记录 `skipped_jd_match_error`，不盲目投递。
- `validateConfig` 增加模式与接口字段校验；`node --check` 通过。
